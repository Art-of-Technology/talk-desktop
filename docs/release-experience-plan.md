# Release experience implementation plan

Scope: consent before native download, short pre-install notes, version-specific post-install notes with optional screenshots, mandatory minimum versions, and human approval of release content before publication. No live feed or installer publication as part of implementation. Windows 2.3.5 remains the live release until the owner approves the next release notes. Shared desktop source must remain brand-neutral.

## Contract

- Fetch `release-manifest.json` relative to the configured HTTPS update feed. Do not invoke Squirrel just to discover updates: its check downloads automatically.
- Manifest: `{schemaVersion:1, latestVersion, releases:[{version,title,summary:[string],sections:[{heading,body,images:[{url,alt,caption?}]}],mandatory:boolean,graceMinutes:integer}]}`. Stable numeric three-part versions; bounded strings/arrays/body; unique versions; latest must exist. Images must be HTTPS within the configured feed origin/path, without credentials or fragments. No remote HTML or scripts.
- The highest mandatory release newer than the installed version sets the minimum required version. Its version is the persisted deadline identity; publishing a newer optional release does not restart that clock. Default grace is 15 minutes, adjustable per approved release (0 means require update or quit). Pending owner preference can change the default before publication.
- Native download uses only a version-pinned feed beneath `releases/<version>/`. Publication must provide its own immutable `RELEASES` and full package. Verify that the native completed version matches the accepted version. Do not replace an accepted release while download/install is in progress.
- Shared state: `{status,version?,message?,release?,mandatory?,deadline?,expired?,persistenceFailed?,whatsNew?,currentRelease?}`. `release` is the latest offered validated release; `whatsNew` is the installed version's exact validated release if unacknowledged. `currentRelease` retains installed notes for menu reopening. `deadline` is epoch milliseconds. Optional failure never invokes installation or closes the app.
- Main-process updater API: `getState()`, async `check()`, `download()` (explicit consent), existing `install({canInstall,prepareQuit})`, `acknowledgeNotes(version)`, `noticeShown()` (starts and persists mandatory clock only once notice can be displayed), `tick()` (rechecks deadline), and `dispose()` if needed. Inject `fetchManifest`, `storage` (`read`, `write` synchronous main-process store), `installedVersion`, `now`, and `onMandatoryExpired`. No renderer-provided feed/policy/identity is accepted.
- Cache validated releases and the active mandatory policy durably under userData, separate from renderer-editable preferences. Restart and transient offline errors preserve a previously observed deadline. Invalid/unavailable metadata never introduces a mandatory policy. Valid newer policy can withdraw a requirement. Acknowledgement is version-specific and persists only on explicit dismissal; stale latest-release notes cannot appear as installed notes.
- UI APIs through preload: existing state/check/install plus `downloadDesktopUpdate()`, `acknowledgeDesktopRelease(version)`, `desktopUpdateNoticeShown()`, `quitForDesktopUpdate()`. Only trusted top-level main chat renderer can consent or acknowledge. Call window does not show competing dialogs.
- Optional prompt: title/version/short benefits; Update now or Skip for now. Download begins only after Update now. Ready prompt offers Restart to update; active calls block optional restart. Mandatory prompt cannot be dismissed, states deadline and call interruption consequence, and offers update or quit. Main process enforces expiration even if renderer is hidden/destroyed. At expiration stop this app's media/windows and exit; never kill external processes. The next launch retains policy until updated or a valid feed withdraws it.
- Post-install dialog shows exact installed version, structured sections and screenshots; explicit dismissal acknowledges it. Main menu can reopen What's new.
- Relaunch after expiry permits only the non-dismissible update-or-quit dialog; new calls are denied. This avoids an immediate-exit loop that would prevent installation. Mandatory persistence failure also locks normal use until the policy can be saved or the app is updated. If no durable policy ever reached disk, an offline relaunch cannot infer an unseen policy.

## Tasks and ownership

1. Updater engine, metadata validation, durable policy and meaningful unit tests (worker: app updater modules and updater tests only).
2. Renderer dialogs, menu, preload/types and UI state tests (worker: renderer updates, MainMenu, preload, typings only).
3. Approval-aware release authoring/staging CLI, publication documentation and AGENTS guidance (worker: scripts/docs/AGENTS only; no real deployment metadata).
4. Parent: main-process wiring, trusted IPC, durable file storage integration and mandatory shutdown. Integrate independent work, test and review, open PRs. No production publication until approved notes.

## Qualification

Test no native check before consent; skip causes no download/install; malformed/missing manifest fails safely; version pin/mismatch handling; mandatory deadlines survive restarts/offline and cannot be dismissed/reset by newer optional release; required update during a call closes only at the advertised deadline; optional update never interrupts a call; post-install notes use installed version and acknowledge once; text/URL safety; stale IPC and concurrent clicks; screenshot rendering; missing images; multi-window ownership. Run scoped tests, lint/type checks and isolated Electron visual smoke. Review PR with Octopus before merge. Do not claim live upgrade or macOS qualification from mocks/Windows.
